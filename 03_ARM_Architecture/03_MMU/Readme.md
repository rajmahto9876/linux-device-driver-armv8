# MMU (Memory Management Unit)
It is hardware inside the ARM CPU that:

- Translates Virtual Address → Physical Address.
- Enforces access permissions.
- Controls cacheability.
- Supports memory protection.
- Generates page faults when translation fails.

Every memory access goes through the MMU (when enabled).
```bash
CPU
 |
 | Virtual Address
 v
+------+
| MMU  |
+------+
 |
 | Physical Address
 v
RAM
```

## Types of Addresses:
| Address Type          | Example    | Used By              |
| --------------------- | ---------- | -------------------- |
| Virtual Address (VA)  | 0x400010   | CPU and applications |
| Physical Address (PA) | 0x81234010 | RAM hardware         |

## Why the MMU

Without the MMU:

- No process isolation
- No fork()
- No mmap()
- No demand paging
- No shared libraries
- No copy-on-write
- No secure user/kernel separation.

## Why Not Use Physical Addresses Directly?

- Imagine Chrome stores a pointer:
```c
char *p = 0x81000000;
```

- If the operating system later moved Chrome elsewhere in RAM:
```bash
	Old RAM
	0x81000000

	↓

	New RAM
	0x92000000
```
- Every pointer inside Chrome would become invalid.
- The OS only updates the page tables. The program continues using 0x400000 without any changes.

```bash
	With virtual memory:

	Virtual Address
	0x400000

	↓

	Old Physical
	0x81000000

	↓

	New Physical
	0x92000000
```

# Address Translation

## Step 1 – CPU Generates a Virtual Address

Example instruction

```asm
LDR X0, [X1]
```
Assume

```
X1 = 0x7F1234567890
```

CPU generates

```
VA = 0x7F1234567890
```

Note: The CPU has **not accessed RAM yet.**

---

## Step 2 – MMU Receives the Address
The MMU receives

```c 
0x7F1234567890
```

It asks, Do I already know this translation?


---

## Step 3 – Check the TLB

The MMU first searches the Translation Lookaside Buffer.

```text
          MMU
           │
           ▼
      +-----------+
      |    TLB    |
      +-----------+
```

Suppose the TLB contains

| Virtual Page | Physical Page |
|--------------|---------------|
| 0x7F12345000 | 0x81234000 |
| 0x7F12346000 | 0x81235000 |

---

### Case 1 – TLB Hit

If the mapping already exists

```text
	VA

	↓

	TLB

	↓

	PA
```

Translation finishes in only a few CPU cycles. This is called TLB Hit

### Case 2 – TLB Miss
Suppose the entry is not present.

Now the MMU must read the page tables.

```text
	CPU

	↓

	MMU

	↓

	Page Table Walk

	↓

	Physical Address
```

This is slower because the processor must access memory to retrieve the translation information.

---

### Step 4 – Page Table Walk

A page table is simply a table stored in RAM.

Example

| Virtual Page    | Physical Page |
|---------------  |---------------|
| 0x1000 		  | 0x8000 		  |
| 0x2000 		  | 0x9000 		  |
| 0x3000 		  | 0xA000   	  |

The MMU searches for the Virtual Page Number.

Suppose

```text
VA Page = 0x2000
```

The page table returns

```text
PA Page = 0x9000
```

Translation succeeds.

---

## Step 5 – Update the TLB

The MMU inserts the new translation into the TLB.

```
Page Table

↓

TLB Updated
```

The next access will likely become a TLB Hit.

# Manually Decode a 48-bit Virtual Address
## Step 1 – ARM64 Virtual Address Layout

For a 48-bit Virtual Address and 4 KB pages:

+---------+---------+---------+---------+------------+
| L0 (9)  | L1 (9)  | L2 (9)  | L3 (9)  | Offset(12) |
+---------+---------+---------+---------+------------+
47      39 38     30 29     21 20     12 11        0

Each level is exactly 9 bits. The offset is 12 bits.

## Step 2 – Example Address
Let's decode, VA = 0x00007F1234567890

The MMU doesn't care about hexadecimal. Internally, everything is converted into binary.

## Step 3 – The MMU Uses Bit Masks:

| Field  | Bits    |
| ------ | ------- |
| Offset | [11:0]  |
| L3     | [20:12] |
| L2     | [29:21] |
| L1     | [38:30] |
| L0     | [47:39] |

## Step 4 – Extract the Bits by Bit masking:

### Take the lower 12 bits.
```c
offset = VA & 0xFFF;
```

### Extract L3 Index
L3 = (VA >> 12) & 0x1FF;

### Extract L2 Index
L2 = (VA >> 21) & 0x1FF;

### Extract L1 Index
L1 = (VA >> 30) & 0x1FF;

### Combined Code:

```c
offset = VA & 0xFFF;
L3 = (VA >> 12) & 0x1FF;
L2 = (VA >> 21) & 0x1FF;
L1 = (VA >> 30) & 0x1FF;
L0 = (VA >> 39) & 0x1FF;
```

# NOTE:
## Q) Why does ARM64 use 9-bit indices in each page table level?
- A page table occupies one 4 KB page. (2^12 = 4096)
- Each PTE is 8 bytes.
- Therefore, one page table contains 4096 / 8 = 512 entries.
- Selecting one of 512 entries requires log₂(512) = 9 bits.

- 4 KB (4096 bytes) is represented as 0x1000 in hexadecimal. 
- This conversion is derived from the fact that 4 KB equals $4 \times 1024 = 4096$ decimal. In base-16, $4096$ is calculated as $16^3$, which corresponds to 1000 in hex digits.

# Phase 4 – Build a Real Identity Mapping
## Phase 4.6 – Virtual Address Decoding

### Step 1 – Start with a 48-bit Virtual Address
- In ARMv8 (4 KB pages), a virtual address is typically 48 bits.	

47                                             0
+-----------------------------------------------+
|           Virtual Address                     |
+-----------------------------------------------+

### Step 2 – Why 4 KB Pages?
- One page is ` 4096 Bytes` i.e., `2^12`
- the lower 12 bits select a byte inside a page.
- The MMU does not use the page offset during translation. It only translates the page number.

47                                    12 11            0
+--------------------------------------+----------------+
|      Virtual Page Number (VPN)       | Page Offset    |
+--------------------------------------+----------------+

### Step 3 – Why 512 Entries Per Table?
- Each table is` 4096 bytes`. Each entry is `8 bytes`. So, `4096 / 8 = 512 entries`
i.e., `512 = 2^9`.
- Each level needs 9 bits to select one of 512 entries.

### Step 4 – Split the Virtual Address
- Starting after the 12-bit page offset:

47       39 38       30 29       21 20       12 11      0

+----------+----------+----------+----------+-----------+
| L0 Index | L1 Index | L2 Index | L3 Index | Offset    |
+----------+----------+----------+----------+-----------+
    9 bits     9 bits     9 bits     9 bits    12 bits

Hence, For Every Entry, the Formaula becomes:

```c
#define PT_INDEX_MASK 0x1FFUL

#define L0_INDEX(va) (((va) >> 39) & PT_INDEX_MASK)
#define L1_INDEX(va) (((va) >> 30) & PT_INDEX_MASK)
#define L2_INDEX(va) (((va) >> 21) & PT_INDEX_MASK)
#define L3_INDEX(va) (((va) >> 12) & PT_INDEX_MASK)

```
