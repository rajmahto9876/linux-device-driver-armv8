# Interrupt vs Exception
## Exception

- Generated by the CPU itself while executing an instruction.

-- SVC
-- Data Abort
-- Instruction Abort
--Undefined Instruction

## Interrupt

- Generated by external hardware.

-- UART
-- Timer
-- Ethernet
-- GPIO
USB
PCIe

These occur asynchronously with respect to the currently executing instruction.

## ARM Interrupt Types:
ARM defines four major exception classes:
- Synchronous
- IRQ
- FIQ
- SError

### 1. Synchronous
- Generated immediately by the instruction being executed.
SVC, BRK, Data Abort, Instruction Abort

### 2. IRQ (Interrupt Request)
- Normal hardware interrupt.
UART, Timer, GPIO, USB

### 3. FIQ (Fast Interrupt)
Originally intended for very low-latency, high-priority interrupts.

Examples:
High-speed data acquisition, Real-time control loops, Safety-critical systems

NOTE:- Modern ARM systems using GIC often rely on interrupt priorities instead of making heavy use of FIQ.

### 4. SError
System error generated by hardware.

Bus errors, ECC failures, External memory faults
Usually indicates severe hardware issues.

## Why GIC:
The GIC centralizes interrupt management by receiving interrupts from peripherals, prioritizing them, and delivering them to the appropriate processor. It works as an interrupt traffic controller.

Responsibilities include:

- Receiving interrupt requests.
- Prioritizing interrupts.
- Enabling/disabling interrupts.
- Routing interrupts to CPU cores.
- Delivering the highest-priority pending interrupt.
- sSupporting inter-processor interrupts (IPIs).

## Main GIC Components:

### Distributor

Global interrupt manager.

Responsibilities:

- Enables/disables interrupts
- Assigns priorities
- Marks interrupts as pending/active
- Routes interrupts to CPUs

it act as the central interrupt database.

### CPU Interface
One per CPU core.

Responsibilities:

- Receives interrupt from Distributor
- Chooses highest-priority pending interrupt
- Signals the CPU
- Allows the CPU to acknowledge and complete the interrupt.

### Redistributor (GICv3+)
Present in newer GIC versions.
Responsibilities:
- Manages per-core interrupts.
- Handles SGIs and PPIs for each processor.

```bash
A byte arrives in the UART.
The UART asserts SPI 33.
The Distributor marks interrupt 33 as pending.
The CPU Interface signals the CPU.
The CPU enters the IRQ vector.
The handler reads ICC_IAR1_EL1 and gets interrupt ID 33.
The UART driver reads the received byte.
The driver clears the UART interrupt source.
The handler writes ICC_EOIR1_EL1.
The CPU executes ERET and resumes the interrupted code.

- The CPU Interface is the CPU's gateway to the GIC.
- ICC_IAR1_EL1 tells the CPU which interrupt occurred.
- Every interrupt transitions through the states: Inactive → Pending → Active → Inactive (or Active + Pending if another event arrives while servicing).

- ICC_EOIR1_EL1 is mandatory to inform the GIC that processing is complete.
- ICC_PMR_EL1 filters interrupts by priority before they reach the CPU.
```

# ARM Priority Scheme
## Priority
- Every interrupt has an 8-bit priority field.
- Example:
| Interrupt      | Priority |
| -------------- | -------- |
| Emergency Stop | 0x10     |
| Generic Timer  | 0x20     |
| Ethernet       | 0x40     |
| UART           | 0x80     |
| USB            | 0xC0     |

- Note: `Smaller numerical value = Higher priority`

## Priority Mask Register (PMR)
- The lower-priority interrupts remain pending until the mask changes.

## Interrupt Preemption
- The lower-priority interrupt is interrupted by the higher-priority one.

## Nested Interrupts
- Every interrupt saves its own context.
- This is why nested interrupts consume stack space.

## Priority Inversion
- High priority waits for low priority.
- Real-time systems try to avoid this by:
-- Keeping ISRs short
-- Deferring long work
-- Avoiding unnecessary interrupt masking

## Block Diagram

```bash
	│      Run New ISR

	└── No

```

# Interview Questions:


## Q1. Why is a lower numerical value a higher priority?
- The GIC compares priority values numerically. A smaller value represents a more urgent interrupt, so it is eligible to preempt interrupts with larger priority values.

## Q2. Can an interrupt interrupt another interrupt?
- Yes. A higher-priority interrupt can preempt a lower-priority ISR if the current priority mask and interrupt configuration allow it.

## Q3. What happens if two interrupts have the same priority?
- They do not preempt each other. One is serviced first, and the other remains pending until the first ISR completes.

## Q4. Why should ISRs be short?
- Long ISRs increase interrupt latency, delay other interrupts, consume more stack space during nesting, and reduce overall system responsiveness.

# ARMv8 Generic Timer & Timer Interrupts
## Generic Timer 
- Instead of each vendor designing a different timer, ARM specifies a Generic Timer architecture.
- Every ARMv8 processor exposes a standard set of timer registers.
- The timer generates a `Private Peripheral Interrupt (PPI)` because it is local to a CPU.

Benefits:
- Linux works across different SoCs.
- Hypervisors have a common timer interface.
- Portable bare-metal software.

## Generic Timer Architecture
- The System Counter is the heart of the timer system.
- It increments continuously from power-on.
- Software never increments it. Hardware does.

## Timer Frequency
- The frequency is stored in:
`CNTFRQ_EL0`

- Read it with:
`MRS x0, CNTFRQ_EL0`

Example:
24,000,000 meaning, 24 million counter ticks per second.
i.e., 1 second -> 24,000,000 ticks

## Reading Current Time
- The current counter value is stored in:
`CNTPCT_EL0`

- Read:
`MRS x0, CNTPCT_EL0`

Example:
987654321, keeps increasing forever (until it wraps after an extremely long time, thanks to being 64-bit).

## Timer Registers

| Register        | Purpose                 |
| --------------- | ----------------------- |
| `CNTFRQ_EL0`    | Counter frequency       |
| `CNTPCT_EL0`    | Current counter value   |
| `CNTP_TVAL_EL0` | Timer interval          |
| `CNTP_CVAL_EL0` | Absolute compare value  |
| `CNTP_CTL_EL0`  | Enable/control register |


# Interview Questions
## Q1. What is the ARM Generic Timer?
- A standardized timer architecture in ARMv8 that provides a common timing interface across different ARM processors using a shared system counter and timer registers.

## Q2. What register stores the timer frequency?
- CNTFRQ_EL0

## Q3. Which register reads the current counter value?
- CNTPCT_EL0

## Q4. Which interrupt type does the Generic Timer generate?
PPI (Private Peripheral Interrupt) because each CPU core has its own timer.

## Q5. Why doesn't Linux poll the timer?
- Polling wastes CPU cycles. Instead, the Generic Timer raises an interrupt exactly when the programmed interval expires, allowing the CPU to perform useful work in the meantime.
